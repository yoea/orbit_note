二、加密模型（理解全库的钥匙）

服务器只存「密文 + 盐 + 哈希」，永远没有 DEK。解密只能发生在用户设备。

1DEK（正文密钥）—— 只在浏览器内存/sessionStorage，服务器永无
2diary_entries.ciphertext = AES-256-GCM(正文, DEK, IV)，每篇独立 IV
3key_wrappers 存 DEK 的加密副本（encrypted_dek）+ 盐 —— 两把「套」：
· passkey_prf：用设备指纹解锁（PRF 输出 → HKDF → KEK → 解出 DEK）
· recovery：用恢复密钥解锁（仅存 SHA-256 哈希，可验证不可反推）
4credentials 存 WebAuthn 公钥 —— 登录时验证签名、给 PRF 授权

key_wrappers ▍3 行
DEK 的「钥匙套」。每把通行密钥一个 PRF 套（2 行），加一个恢复密钥套（1 行）。
字段类型约束说明
iduuidPK内部 ID
wrapper_typetextcheckpasskey_prf（设备指纹解锁）或 recovery（密钥解锁）

🔒 约束：PRF 套按 (type, credential_id) 唯一——每把钥匙恰好一个套；recovery 全库唯一一行。

四、表间关系

→key_wrappers.credential_id → credentials.credential_id：每把通行密钥对应一个 PRF 钥匙套；禁用/删除凭证时同步清理其套
→key_wrappers.recovery_key_hash ↔ credentials：无外键——恢复密钥登录独立于任何设备凭证（灾难恢复通道）
→diary_entries / drafts：与密钥体系无直接外键——正文解密靠「客户端 DEK + 服务器盐」，由加密协议而非外键连接
→user_prefs / prompt_stats：独立工具表，无关联

五、业务数据流速览

✍️写一篇日记：定位/天气可选 → 客户端 AES 加密 → diary_entries 插入密文 → 异步反查地点名/天气补写
🔓解锁：通行密钥认证（验 credentials 签名）→ PRF 输出 + salt → KEK → 解开 key_wrappers → DEK 进内存 → 本地解密 diary_entries
📊热力图/统计：只读元数据（created_at/timezone/word_count）——免解密、毫秒级
🗂️设置：偏好读 user_prefs → 写 localStorage → 改动回写；Passkey 管理操作 credentials + key_wrappers
